# 整合式影像處理軟體

以高解析度灰階影像為主的 Windows 桌面影像處理與檢測工具。技術採用 C# WinForms、.NET Framework 4.7.2 與 OpenCvSharp。

## 專案狀態

- 文件快照：2026-10-23；本機 `main` 與 `origin/main` 均指向 `a3f65d6`（`Improve controller connectivity and recipe status`）。目前另有六個 C# 檔與兩份文件的未提交修改，包含導覽防重建、頻域效能及一般缺陷／頻域協同平行；本次文件更新不包含提交或推送。
- 線掃描取像已整合為獨立 `CameraCaptureModule`，嵌入「全域設定 → 與線掃描取像結合」；相機原有設定／波形等彈出視窗保留。「顯示攝影機影像」控制原本的相機預覽區；送檢開關會以目前選取參數執行物件搜尋、尺寸量測及缺陷判定。若新影像進來時使用者正在「檢測總覽」，畫面保持在總覽：新圖先以待確認狀態顯示，判定完成後更新各物件尺寸、缺陷與綜合結果。尚未完成相機實機端到端驗收，流程仍透過暫存 TIFF 與結果確認 UI 運算，不是生產用純記憶體檢測服務。
- 提交 `a3f65d6` 包含獨立的「參數選擇」、作用中 Recipe 狀態同步、攝影機監控開關，以及依存活 TCP peer 更新檢測總覽燈號。2026-10-23 本機導覽修正讓同一目標或空白選取不重設右側，群組展開／收合保留目前內容；同名不同參數與替換後沿用 ID 的 Recipe 仍會切換至正確設定實例。最新版本通過 70 項隱藏 WinForms 導覽／MEMO 檢查；跨 Recipe 完整 GUI 與相機實機尚未驗收。
- 缺陷檢測範圍組可由勾選框選成員、將已勾選 ROI 上下排序；物件序號下方另有「顯示檢測範圍的 ROI 框」開關。選到物件時可顯示目前條件所選群組的 ROI；未選群組仍須核對預覽與運算一致性。
- 左側「參數選擇」是獨立主項目，位於可收合的「檢測參數」上方；「檢測參數」展開後只包含新建、讀取與加入、更新目前 Recipe、另存新 Recipe 四個操作。新建會清空檢測設定並解除作用中 Recipe，但保留圖片、Recipe 清單及全域內部參數；更新會確認後覆寫作用中 Recipe；另存會建立新 Recipe 並切換為作用中項目。尚待 GUI 驗收。
- Recipe 參數管理可將參數檔加入軟體根目錄 `recipe`、編輯名稱與說明、調整清單順序，以及選取一組套用；套用後會重新跑相關物件流程與已啟用的缺陷分析。
- 平場校正設定或 MASK 變更造成的過期工作取消，已改為預期取消而非未處理錯誤；需在快速切換設定的 GUI 情境確認取消與新工作結果。
- 紋理異常判定已從設定介面、運算流程、結果整合、結果確認及參數保存中移除；平場分支、條件一至六與頻域異常一／二保留。Debug 建置成功，尚待 GUI 頁籤與舊 Recipe 載入行為確認。
- Recipe 選擇視窗排版與文件均已更新；獨立輸出 Debug 建置成功。結果確認中的多類缺陷分析已支援依參數勾選平行執行，但尚未完成真實產線影像端到端驗收。
- 結果確認已保存最近一次成功執行的記憶體快照；離開頁面操作其他功能後，只要圖片和檢測參數未改變，就還原結果與每個影像頁的縮放／平移狀態。載入新圖或參數簽章改變時，舊結果失效，需重新執行確認。
- 檢測範圍採「全物件共用 ROI 定義＋ROI 群組」：每個 ROI 有穩定 ID 與唯一名稱，以參考物件的局部比例定義位置，再映射到同一物件定義下所有已找到物件；群組只保存多個 ROI ID。七個一般缺陷分支及頻域一／二各自選群組，同組重疊 ROI 以遮罩聯集處理，不重複檢測。舊參數會在讀取時遷移／整理；最新程式已 Debug 建置成功，尚未完成 GUI／實圖驗收。
- 頻域區域能量與結果整合已在程式中；2026-10-23 完成 MASK 快速查詢、選用鄰格統計與暫存重用。新舊版本 23,432 個視窗及 72 組完整 ROI 流程比對一致；實際公司影像的異常框、總耗時及整體 NG 仍待驗收。大圖平移／清晰度也仍待使用者以實際圖片確認。
- 設定頁的「執行缺陷檢測」已將啟用的頻域一、二納入平行排程，保留逐片／逐條件平行、單頁套用與關閉平行時的依序路徑。46 項合成影像排程／輸出檢查通過，一般 `bin/Debug` 執行檔已更新；「四片 × 四流程」是 16 個可排程工作，不保證固定建立 16 條專用執行緒。

## 主要流程

```text
原圖
  -> 前處理
  -> 影像處理（Edge / Threshold）
  -> 影像關聯
  -> 整合區塊與區塊處理
  -> 物件定義（連通元件、篩選、編號、可選旋轉資訊）
  -> 檢測參數（平場、尺寸量測、良品條件、檢測範圍組、平場＋條件一至六、頻域異常一／二）
```

檢測參數包含尺寸量測與尺寸良品條件、平場校正、七個一般缺陷分支（平場影像與條件一至六）及兩組頻域異常分析。各分支有獨立設定與預覽；套用單一分支只更新該分支。執行全部缺陷檢測時，開啟平行會在共用平場影像準備後，同時排入一般分支與已啟用的頻域一、二；關閉平行則依序執行。結果確認頁在平行設定開啟時也可同時執行缺陷與需要補算的頻域分析。

每個 ROI 是共用定義，以參考物件的局部座標比例保存；運算時將相同比例映射到該物件定義下所有已找到物件的局部框。ROI 名稱必須唯一，但群組關聯使用穩定 ROI ID，因此重新命名不會讓群組失去對應。ROI 群組是多個 ROI ID 的集合；各一般缺陷／頻域條件選擇群組後，對每一枚物件使用該組 ROI 的遮罩聯集進行處理，同一組內重疊範圍不重複檢測。設定保存於 `SystemParameters.ini`，不會自動覆寫 `recipe/<ID>.ini`；重新套用舊 Recipe 可能載回舊 ROI／群組。此比例映射假設物件的局部方向與相對位置一致，仍需用不同尺寸、旋轉與定位的實際物件驗收。

「參數結果確認」是唯讀檢測流程：選擇已保存的檢測參數、載入相同影像尺寸的圖片，再按「執行確認」。左側可切換量測位置、平場校正、缺陷平場／條件一至六、頻域異常一／二與整合結果；右側檢視量測統計、尺寸良品條件和缺陷判定。尺寸條件先判 A 規，A 不符合才判 B 規，B 規可獨立使用。此頁不提供參數編輯；實際圖片結果仍待驗收。

目前規劃的使用流程是工程師先設定檢測參數，使用者再選擇參數與圖片、明確執行檢測並查看影像和判定；設定與檢視分開的方向合理。尚未完成的檢測設定防呆、判定政策確認及實圖驗收，是後續完善項目，不代表流程規劃需要重做。

## 全域設定與取像

- 左側「全域設定」開啟獨立頁面，分為「與線掃描取像結合」及「內部參數」。取像頁嵌入原攝影機程式的完整主操作畫面，原有相機設定、波形及測速輪等彈出視窗仍獨立開啟；模組首次顯示時才初始化。此頁不顯示主檢測影像／參數編輯區。
- 「取得影像後事件」有兩個獨立勾選：「顯示攝影機影像」控制相機原有預覽區；取消後清除目前即時影像並停止預覽影格轉換／繪製，但不停止取像、記錄、自動保存或送檢。設定頁沒有新增第二個影像顯示框。
- 「將取得的影像送入影像處理」預設關閉。啟用時，`ICameraImageSource.ImageAcquired` 事件會把完成影格傳給主程式；主程式複製影格、檢查尺寸，保存至 `%LocalAppData%\IntegratedImageProcessingApp\CameraFrames\` 暫存 TIFF，再以目前選取的 Recipe 執行物件搜尋、尺寸量測、平場及啟用中的缺陷／頻域分析。每次只處理一張，忙碌時新影格略過、不排隊。
- 「連線總控參數 > 連線行為」新增「是否監控攝影機」主開關。取消勾選並保存後，不會自動連線或重連，既有被控站點連線會中斷，總控頁面的連線／取像／檢測操作停用；舊 XML 缺少此欄位時預設啟用以維持相容。總控狀態所傳 Recipe ID／名稱來自目前作用中的 Recipe，而非舊檢測結果快照；載入、更新、另存或改名後會刷新狀態。
- 若取像前正在「檢測總覽」，新圖先顯示待確認，再於原頁更新尺寸、缺陷及綜合判定；使用者運算中自行切頁時不強制拉回。這條路徑仍借用「參數結果確認」控制項與運算狀態，但不必為運算把總覽切換成結果確認頁；從其他頁面取像的結果會保存在快照。總覽固定使用原始輸入影像，不疊加缺陷標記。
- 這是目前已接通的 UI 驗證路徑，不是純記憶體的獨立 pipeline；尚未實機驗證，也尚無生產級錯誤重試、逾時、結果持久化或整體併發管理。未來應抽出接收 Bitmap／Recipe 快照的檢測服務，讓相機與人工載圖共用，避免檢測核心依賴 UI 導覽與暫存檔。

## 檢測總覽

- 左側固定顯示最近一次完成檢測的原始影像，不在底圖疊加缺陷框；右側以物件定義的序號與排列位置建立格子。
- 每個物件格呈現尺寸、缺陷、綜合三項判定；尺寸 A/B/NG、缺陷 A/NG/待確認分開顯示，尺寸或缺陷任一 NG 則綜合 NG，若結果未完成則綜合待確認。
- 單擊物件格會聚焦影像到該物件並在左下區域查看三項結果；再次雙擊同一格會清除選取框並恢復全圖視野。頁面可依全部、NG、待確認篩選，並可將選取物件送到「參數結果確認」檢視。
- 頁首 TCP/IP 燈號依本機 TCP 傳輸中存活的連線 peer 顯示；任一總控端或被控端連線建立時轉為綠燈「已連線」，全部斷開時回到灰燈「未連線」，並在連線狀態事件後刷新。
- 相機送檢成功後會更新最近結果快照；若總覽原本正在顯示，流程完成後返回並刷新總覽原始影像。暫存 TIFF／Result Review UI 的耦合、忙碌時丟棄影格及相機實機驗收是目前限制。
- 相機設定使用執行檔目錄的 `captureSetting.ini`；首次找不到時會從同一目錄的舊 `settings.ini` 或 `setting.ini` 複製遷移。若舊設定仍在獨立相機程式的輸出資料夾，首次開啟整合程式前先把舊檔放到主程式執行檔旁，才會沿用原設定。預設影像儲存於 `CameraCapture/Captures`，相機記錄寫入 `logs/camera/app.log`。攝影機設定、資料與 `config/device-settings.ini` 保持分離。
- 「內部參數」設定攝影機 X/Y 精度（mm/pixel）與是否啟用 mm 換算。程式啟動時讀取執行檔目錄的 `config/device-settings.ini`；缺檔時 X/Y 預設 1、mm 換算關閉，尺寸量測以 pixel 計算。單一精度值無效時該軸回退為 1，但若檔案仍設定啟用 mm 換算，開關不會自動關閉；現場需檢查完整設定。套用後寫入此檔，不隨 Recipe 切換。
- 舊 Recipe／`SystemParameters.ini` 中的攝影機精度欄位不再讀寫，也不自動轉入全域設定檔。缺陷 X/Y 尺寸門檻仍以全域 X/Y 精度換算 pixel；即使尺寸量測的 mm 換算未啟用，也不可把預設 1 mm/pixel 誤當成已標定的實際精度。換機或使用舊參數前須校對全域設定。
- 尺寸、缺陷與結果確認已接用全域精度；結果確認簽章包含 X/Y 精度與換算開關，設定變更後舊結果需重算。此路徑仍須以 GUI、舊 Recipe 和標定影像驗收。

## 架構評估

- **流程方向合理**：設定、執行與唯讀結果檢視的職責有區分，物件 ROI、平場、尺寸量測、缺陷核心與結果整合的處理順序清楚。
- **程式仍屬單體 WinForms 的逐步拆分階段**：`partial MainForm` 讓功能比較容易定位，但各檔案仍共享主視窗狀態；拆檔尚不等於模組可獨立測試或執行。
- **結果確認已隔離已完成結果的保留**：以記憶體快照保存參數、影像來源、物件、MASK、分析結果及各顯示頁視圖狀態，跨功能切頁不會自行清掉結果；影像或參數變更會使快照失效並要求重跑。但執行協調仍位於 `MainForm`，目前不是完全獨立的運算工作階段，也不會跨程式重啟保存。
- **平行運算需以實圖確認資源上限**：設定頁會同時排入一般條件與啟用的頻域一／二；結果確認則同時排入一般條件及需要補算的頻域。各流程內部仍可能依物件 ROI 平行，不是固定建立「ROI 數 × 核心數」個執行緒；仍需測量 CPU／記憶體壓力及取消行為。
- **巢狀平行度尚未集中限制**：一般缺陷有物件 ROI 與分支兩層 `Parallel.For`，頻域也可按物件平行，這些上限主要依輸入數量設定；尺寸量測另有 CPU 數／最多 8 的限制。尚無跨尺寸、一般缺陷與頻域的共同併發／記憶體預算，大量物件或大圖仍需實機壓力測試。
- **共用 ROI 的比例映射是關鍵驗收項目**：ROI 不再依物件序號建立不同副本；使用參考物件定義的正規化局部矩形，套用至同一物件定義下所有已找到物件。若物件尺寸比例、旋轉方向或局部結構不一致，固定比例可能不是每枚物件都適合的檢測位置。需以尺寸差異、旋轉物件、定位偏移及部分物件漏檢的代表影像確認框位與遮罩聯集。
- **Recipe 與作用中設定的保存範圍需分清楚**：修改 ROI 組時會保存目前系統參數，但不會自動更新 Recipe 原檔。要把修改納入 Recipe，使用既有的「更新目前recipe」或「另存為新的Recipe」；兩者不能與一般參數頁的套用混為一談。
- **攝影機精度已改為設備層設定**：`config/device-settings.ini` 與 Recipe 分離；切換 Recipe 不會替換 X/Y 標定值。缺檔時的 1 只是保護性預設，不能用於實際 mm 判定的驗收。
- **相機已接到檢測總覽的初步流程，尚未產品化**：送檢開關啟用時，影格使用目前選取參數執行物件搜尋、尺寸與缺陷分析，成功快照可更新總覽影像及每物件判定；從總覽取像時，成功後返回總覽。運算仍切換／借用結果確認 UI、經暫存 TIFF，忙碌時丟棄新影格；尚未拆成純記憶體服務，也未完成實機壓力、錯誤恢復、逾時及結果追蹤驗收。長時間設備運轉前應抽出獨立檢測 pipeline，並明確定義丟棄策略與結果契約。
- **參數持久化可維護性是風險**：設定模型為強型別，但 INI 讀寫採手動欄位序列化；目前沒有明確的格式版本／遷移機制，舊參數相容性需持續驗證。
- **Recipe 與作用中設定**：多個 Recipe 可存於目錄並供使用者選擇，但同一時間只有一組載入為作用中設定；套用會替換目前設定並自動重跑相關流程，不是兩組參數同時執行的隔離工作階段。
- **驗證基礎仍需補強**：目前未找到專用自動化測試專案；建置成功不能替代影像算法、參數往返與 GUI 端到端驗收。

下一步優先驗證單一 ROI 對所有物件的比例映射、同組重疊 ROI 聯集、不同條件使用不同 ROI 群組、ROI 邊界裁切及舊 Recipe 遷移，再為 ROI 解析與參數往返建立測試。長期再明確化檢測工作階段的輸入／輸出契約，逐步抽離純運算服務並限制平行度與影像記憶體用量，避免只為降低檔案行數而大規模重寫。詳細風險與建議順序見 [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md)。

- 大圖平移時，依可視區域大小限制快取磚塊繪製數；上限目前為 64 塊，超過時以預覽圖保持拖曳流暢，放開後再載入細節。

- 待量測畫面的平行線疊圖會依縮放抽樣顯示；量測計算仍使用完整線數。獨立線段繪圖也已避免路徑意外相連。
- 使用者回報 `0.03X` 拖曳順、`0.04–0.06X` 曾卡頓，`0.14X` 曾模糊。64 塊上限與 3072 預覽是最新折衷，尚待使用者用同一張大圖確認流暢度、清晰度與 MASK 對位。
- 最近發現結果確認的平場、條件及頻域頁在剛放開滑鼠後立即再平移會短暫卡住，整合頁較順。推測各頁自訂 overlay 的每次重繪成本不同；這是程式路徑檢視所得，尚未用 profiler 量測。更完整的優化應快取／預先繪製 overlay，避免 Paint 時反覆建 Mat 或走訪大量輪廓／格子。

## 結果確認的結果保留

- 每次成功執行後，記憶體快照保存該次參數與設定簽章、原圖／校正圖來源、物件、量測 MASK、平場 MASK／結果、一般缺陷／頻域結果、整合群組及各影像頁縮放平移狀態。
- 離開結果確認去操作其他流程再回來，只要來源影像與設定未變，就恢復結果與視圖，不需重跑。載入新圖片或檢測參數／物件定義簽章改變時，舊結果會失效；按「執行確認」才以新輸入重新運算。
- 快照只在目前程式執行期間保留，並非持久化結果檔。此功能讓顯示結果不再因其他流程切頁而消失，但計算流程仍由 `MainForm` 協調，不能視為完全獨立的檢測服務。

## 頻域分析近況

- 頻域預覽與掃描共用同一份 8-bit 灰階影像；「啟用對比調整」勾選時，在平場校正影像上套用對比倍率，取消時使用倍率 1.0。舊參數缺少此欄位時預設啟用，維持原本行為。
- 目前僅執行重疊視窗的區域能量分析，並顯示能量熱圖及異常框。原本將完整 DFT 頻譜功率加總，現以 Parseval 等價的 MASK 內加窗平方平均計算；保留視窗尺寸、半格步距與結果統計定義，不再為全頻譜總和執行 DFT。
- 灰階平均及 Hanning 加窗能量仍使用原本的列指標與浮點計算順序。完整／空白／實心矩形 MASK 使用精確快速判定；不規則 MASK 以滑動欄計數與位元查詢表處理當前掃描列，額外查詢資料每個 ROI 上限 8 MiB，超過時回退原始逐像素檢查，不限制可檢測影像尺寸。檢查仍要求整格有效，保留原本邊界往內搜尋順序。
- 關閉鄰近良品比較時略過 4×4 子區塊統計；開啟時重用陣列及預先計算的分區索引。垂直倍率 0.25／0.5／0.75／1／2／3 仍逐格使用原本的裁切、Resize 插值及分析高度，並未改成整張影像縮放。計算區塊使用受控 unsafe 記憶體存取，專案已啟用 `AllowUnsafeBlocks`。
- 分析狀態會分列平場來源準備、掃描牆鐘、掃描格數，以及 ROI 格迴圈／預覽的累計時間；平行處理時累計時間可能大於實際等待時間。真正畫面重繪時間不包含在分析總耗時內。
- 左下 MEMO 額外列出各 ROI 工作累計：影像準備、對比、前處理、MASK／座標校正、MASK 查詢準備、有效格搜尋、垂直縮放、能量／灰階統計與預覽。結果確認保留原本整體牆鐘計時；頻域細項標示「最近結果」，可能來自重用快取，不能直接加到本次總時間。頻域頁面原本控制項位置不變。
- 2026-10-23 在本機 Debug、固定單一 OpenCV 執行緒，以 4000×8000 合成灰階圖、500 px 視窗各測三次取中位數。完整 MASK／1 倍／鄰格關閉的掃描核心由 1227 ms 降至 582 ms；鄰格開啟由 1229 ms 降至 730 ms。這些數值不包含取像、平場、ROI 前處理或 UI 顯示，不代表公司影像整體流程也會加快相同比例。
- 自動方向線分析及其敏感度／熱圖／異常框設定已從介面、運算和參數保存移除；舊 INI 內相關未知欄位會被忽略，重新保存時不再寫出。
- 「結果整合」可選擇納入頻域異常；只把有效結果中的異常掃描格作為中性候選，與暗／亮缺陷依 ROI 和合併距離分組，且不繞過既有暗／亮／亮暗合併限制。來源會列為「頻域異常」，頻域單獨群組用青色框。
- 結果確認中若選擇納入且頻域啟用，會重用有效頻域快取，沒有有效結果才自動分析；頻域分析失敗或過期會將整合判定設為待確認。整合群數會影響缺陷 NG 判定。

## 缺陷與結果確認平行運算

- 檢測參數設定的「執行缺陷檢測」啟用平行時，以 `Task.WhenAll` 等待一般條件與啟用中的頻域一、二；一般條件仍可按物件／分支平行，頻域仍可按物件平行。單頁套用不會連帶重跑其他分支，未啟用的頻域不排入工作。
- 頻域的影像前處理與掃描可先執行；若啟用鄰格比較，最後排除一般缺陷區的比較會等待本輪一般條件完成，不讀取尚未更新的缺陷結果。左下 MEMO 新增「缺陷全部檢測並行牆鐘（含結果更新）」，不加總各分支耗時；此值不含開始平行前的共用平場來源準備，也不代表實際畫面重繪時間。
- 結果確認只要求已啟用、且「納入結果整合或啟用鄰格比較」的頻域；缺少有效結果或輸入設定變更時才補算。平行選項開啟時，這些頻域與一般條件用 `Task.WhenAll` 一起排程；尺寸量測另與缺陷計算同時執行。
- 平行缺陷總耗時使用共同工作的牆鐘時間，不把各任務耗時相加；各演算法內部仍可能按物件 ROI 平行，因此實際效能取決於 ROI 數、影像大小、快取與硬體。
- 關閉平行時，一般缺陷分支和頻域依序執行；結果確認原本的「尺寸與缺陷同時執行」不由此缺陷平行開關取消。單頁套用／單獨頻域分析只處理該頁，各自仍依勾選決定是否按片平行。
- 已通過合成圖排程與結果回歸；尚需以新圖片完整執行，驗證實際耗時、記憶體用量、取消與例外收尾。全解析度預覽產圖、不處理時的影像複製、結果確認的兩階段鄰格比較及整合 UI 更新仍是後續效能候選，不能因為已啟用平行就視為所有成本已消除。

## Recipe 參數管理

- 左側「參數選擇」獨立顯示並位於「檢測參數」上方；「檢測參數」主項目可收合／展開，預設收合，展開後顯示四個操作入口。
- 「新建參數」經確認後會以空白 `SystemParameterSettings` 重置目前 `SystemParameters.ini`，清除 ROI、找物件流程、尺寸／缺陷檢測設定及作用中 Recipe ID；保留目前圖片路徑。全域內部參數保存在獨立的 `config/device-settings.ini`，不會被重置；Recipe 清單與現有 Recipe 檔也不會被刪除。
- 「參數讀取與加入」會將參數檔加入軟體根目錄的 `recipe` 資料夾；加入不會立即改變目前流程。
- 「參數選擇」可查看 Recipe 名稱與說明、編輯中繼資料、調整並保存清單順序、刪除未使用的項目，並在明確按下套用後切換作用中參數。它是「檢測參數」上方的獨立導覽項目，不會隨該主項目收合。
- 「更新目前recipe」會先要求確認，再將目前設定覆寫至作用中 Recipe，並更新其修改時間；若目前設定無法唯一對應 Recipe，會阻止覆寫。
- 「另存為新的Recipe」會以目前檢測設定建立新的 Recipe ID，讓新項目成為作用中 Recipe。Recipe 快照不帶入目前圖片路徑或作用中 Recipe ID；此操作不會自動重跑影像流程。
- `recipe/parameterList.json` 保存 Recipe ID、名稱、說明與排序；每份完整參數另存為 `recipe/<ID>.ini`。目前匯入檔需包含且只包含一組檢測參數。
- 套用後會保存作用中 Recipe ID，檢查物件定義結果是否有效，必要時重跑物件流程，再套用參數保存的平場 MASK／校正值與執行已啟用的一般缺陷分支及頻域分析。一次只載入一組作用中設定；套用和自動重跑仍待 GUI 與代表性圖片驗收。詳見 [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md)。
- 跨 Recipe 載入時會取消舊工作、清除結果／快取及動態選單的索引映射，再以新設定重建 ROI、找尋物件與檢測參數項目；物件檢測參數選取以穩定 ID 對應。若映射不存在，仍有依顯示名稱尋找的回退路徑，因此同一 Recipe 內的重複顯示名稱，以及連續切換不同項目數量的 Recipe，仍須實際操作驗收。
- 2026-10-23 共用導覽入口會比較目前設定實例、實際功能目標及顯示名稱；重複選取同一目標直接返回，不先退出總覽或重建面板。空白選取不改畫面；群組的展開符號變更不視為換功能。同名不同參數、換 Recipe 及明確重設仍會更新；切換檢測參數／物件定義編輯器時釋放舊控制項。取圖、選配方及明確執行處理等命令仍可重複操作。

## 建置

以 Visual Studio 開啟根目錄的 `MyApp4.sln`，還原 NuGet 套件後選擇 `Debug` / `Any CPU` 建置（執行檔和相機模組實際以 x64 編譯）。Sapera managed SDK 與測速輪 x64 DLL 預設分別從相機專案的輸出資料夾取得；其他位置請指定 `CameraSdkDirectory` 和 `LsiNativeDirectory`：

```powershell
msbuild .\MyApp4.sln /t:Build /p:Configuration=Debug /p:Platform="Any CPU" /p:CameraSdkDirectory="C:\path\to\Sapera" /p:LsiNativeDirectory="C:\path\to\LSI\x64"
```

主專案為 `IntegratedImageProcessingApp\IntegratedImageProcessingApp.csproj`。此舊式 .NET Framework 專案使用明確的 `<Compile Include=...>` 清單；新增 C# 檔案時要一併更新專案檔。

## 程式結構

- `IntegratedImageProcessingApp\Controls`：影像顯示、縮放平移、大型影像來源與預覽／分塊繪製。
- `CameraCaptureModule`：從攝影機取像專案複製到主方案的獨立 x64 WinForms 模組，含相機服務、主操作視窗及其原有彈出視窗；後續原相機專案更新不會自動同步到此模組。由 `CameraCaptureHostControl` 嵌入主程式全域設定頁。
- `IntegratedImageProcessingApp\Controls\CameraCaptureHostControl.cs`：延遲建立／承載相機主視窗；送檢開啟時訂閱並轉送完整影格事件，並於主程式關閉時釋放相機。
- `IntegratedImageProcessingApp\Forms\MainForm.CameraCapture.cs`：接收相機影格、處理忙碌丟棄／尺寸檢查／暫存 TIFF，以目前參數啟動結果確認，成功時將結果交給總覽。
- `IntegratedImageProcessingApp\Forms\MainForm.ConnectionController.cs`：總控端站點連線、狀態卡片與 TCP 命令；目前 Recipe 狀態由作用中 Recipe ID 與 `parameterList.json` 名稱解析。
- `IntegratedImageProcessingApp\Services\ConnectionControllerSettingsService.cs`：總控站點與連線行為 XML 設定模型／讀寫，含 `MonitorCamera` 監控主開關。
- `IntegratedImageProcessingApp\Forms\MainForm.InspectionOverview.cs`：顯示完成檢測的影像、物件矩陣、尺寸／缺陷／綜合判定、篩選及送往結果確認的操作。
- `CameraCaptureModule\Forms\CameraSettingsForm.cs` 與 `CameraCaptureModule\Forms\MainForm.cs`：設定兩個獨立事件開關；顯示開關控制原預覽區，送檢開關控制完整影格事件訂閱。
- `IntegratedImageProcessingApp\Forms`：WinForms 主視窗與各功能流程；`MainForm` 以 partial 檔分工，仍負責主要 UI 協調。
- `IntegratedImageProcessingApp\Services`：OpenCV 運算、INI 參數、灰階解碼及 ROI／MASK 快取與建置。
- `IntegratedImageProcessingApp\Forms\MainForm.GlobalSettings.cs`：全域設定頁、攝影機 X/Y 精度、總控連線行為與站點清單 UI。

- `IntegratedImageProcessingApp\config\device-settings.ini`：隨建置複製到輸出目錄的設備設定初始檔；執行時使用輸出目錄中的檔案。
