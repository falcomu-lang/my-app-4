# 整合式影像處理軟體

以高解析度灰階影像為主的 Windows 桌面影像處理與檢測工具。技術採用 C# WinForms、.NET Framework 4.7.2 與 OpenCvSharp。

## 專案狀態

- 文件快照：2026-10-05。
- 近期已推送基底為 `5db8df2`（`Reduce false positives in directional line analysis`）；本次加入頻域影像來源對比開關，並更新參數保存／讀取。
- 本次程式修改已通過 Debug 建置；尚未啟動 GUI 驗證控制項，也未以使用者的實際影像完成端到端驗收。
- 此前的大圖平移與清晰度調整曾完成建置，但本次未重新建置；仍待以實際影像驗收，建置成功也不代表拖曳效能或影像品質已確認。

## 主要流程

```text
原圖
  -> 前處理
  -> 影像處理（Edge / Threshold）
  -> 影像關聯
  -> 整合區塊與區塊處理
  -> 物件定義（連通元件、篩選、編號、可選旋轉資訊）
  -> 檢測參數（平場、尺寸量測、良品條件、缺陷四核心、頻域異常）
```

檢測參數包含尺寸量測與尺寸良品條件、平場校正、四個缺陷檢測核心，以及頻域異常分析。各缺陷核心有獨立設定與預覽；單核心「套用」只更新該核心，「執行四核心檢測」才執行全部核心。頻域頁可用平場校正灰階影像與對比倍率分析區域能量，另有不需指定角度的方向線分析。影像 MASK 來源、檢測範圍及結果保存方式詳見專案交接文件。

「參數結果確認」是唯讀檢測流程：選擇已保存的檢測參數、載入相同影像尺寸的圖片，再按「執行確認」。左側切換量測位置、平場校正、缺陷平場／條件一至三與整合結果；右側檢視量測統計、尺寸良品條件和缺陷判定。尺寸條件先判 A 規，A 不符合才判 B 規，B 規可獨立使用。此頁不提供參數編輯；實際圖片結果仍待驗收。

目前規劃的使用流程是工程師先設定檢測參數，使用者再選擇參數與圖片、明確執行檢測並查看影像和判定；設定與檢視分開的方向合理。尚未完成的檢測設定防呆、判定政策確認及實圖驗收，是後續完善項目，不代表流程規劃需要重做。

## 架構評估

- **流程方向合理**：設定、執行與唯讀結果檢視的職責有區分，物件 ROI、平場、尺寸量測、缺陷核心與結果整合的處理順序清楚。
- **程式仍屬單體 WinForms 的逐步拆分階段**：`partial MainForm` 讓功能比較容易定位，但各檔案仍共享主視窗狀態；拆檔尚不等於模組可獨立測試或執行。
- **結果確認尚未完全隔離執行狀態**：結果確認頁會設定目前作用中的參數，並沿用主視窗的圖片、物件定義與平場校正流程。雖然操作頁是唯讀的，內部仍可能受共用狀態影響，尚未成為獨立的檢測工作階段。
- **平行運算需以實圖確認資源上限**：目前 ROI 與核心層皆可平行，且各 ROI 會保留多核心結果與預覽。工作單位數不等於固定執行緒數，但嵌套排程和影像暫存仍可能造成 CPU／記憶體壓力。
- **參數持久化可維護性是風險**：設定模型為強型別，但 INI 讀寫採手動欄位序列化；目前沒有明確的格式版本／遷移機制，舊參數相容性需持續驗證。
- **驗證基礎仍需補強**：目前未找到專用自動化測試專案；建置成功不能替代影像算法、參數往返與 GUI 端到端驗收。

建議優先建立「檢測工作階段輸入快照／結果快照」，使結果確認不再借用主流程的可變狀態；再為尺寸計算、缺陷分割與合併、參數讀回建立測試。之後逐步抽離純運算服務、設定平行度上限與影像記憶體用量，避免只為降低檔案行數而進行大規模重寫。詳細風險與建議順序見 [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md)。

## 最近顯示效能調整

- 大圖平移時，依可視區域大小限制快取磚塊繪製數；上限目前為 64 塊，超過時以預覽圖保持拖曳流暢，放開後再載入細節。
- 預覽長邊上限提高至 3072，改善中低倍率預覽被放大時的模糊。
- 待量測畫面的平行線疊圖會依縮放抽樣顯示；量測計算仍使用完整線數。獨立線段繪圖也已避免路徑意外相連。
- 使用者回報 `0.03X` 拖曳順、`0.04–0.06X` 曾卡頓，`0.14X` 曾模糊。64 塊上限與 3072 預覽是最新折衷，尚待使用者用同一張大圖確認流暢度、清晰度與 MASK 對位。

## 頻域分析近況

- 頻域預覽和頻域／方向分析共用同一份 8-bit 灰階影像；「啟用對比調整」勾選時，在平場校正影像上套用對比倍率，取消時使用倍率 1.0。舊參數缺少此欄位時預設啟用，維持原本行為。
- 自動方向線分析使用 OpenCV Sobel 方向一致性，不是逐格列舉固定角度，也不會輸出單一線段座標或角度。方向分數依同一物件內各掃描格的差異與最低方向一致性門檻計算。
- 曾試行逐掃描格執行 Hough 線段搜尋，遇到執行過慢及標示過多；`5db8df2` 已移除此路徑，改回輕量方向一致性並加上雙門檻，減少整片誤標。
- 最新修改只完成建置，尚未用出現 20 度斜線的實際影像確認「能檢出且不滿版」。

## 建置

以 Visual Studio 開啟根目錄的 `MyApp4.sln`，還原 NuGet 套件後選擇 `Debug` / `Any CPU` 建置。也可使用：

```powershell
msbuild .\MyApp4.sln /t:Build /p:Configuration=Debug /p:Platform="Any CPU"
```

主專案為 `IntegratedImageProcessingApp\IntegratedImageProcessingApp.csproj`。此舊式 .NET Framework 專案使用明確的 `<Compile Include=...>` 清單；新增 C# 檔案時要一併更新專案檔。

## 程式結構

- `IntegratedImageProcessingApp\Controls`：影像顯示、縮放平移、大型影像來源與預覽／分塊繪製。
- `IntegratedImageProcessingApp\Forms`：WinForms 主視窗與各功能流程；`MainForm` 以 partial 檔分工，仍負責主要 UI 協調。
- `IntegratedImageProcessingApp\Services`：OpenCV 運算、INI 參數、灰階解碼及 ROI／MASK 快取與建置。

完整檔案職責、功能進度、資料保存語意、建置狀態、已知限制與接手驗收步驟請見 [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md)。

## 驗收狀態

最近一次 Debug 建置成功，輸出至 `IntegratedImageProcessingApp\bin\ContrastToggleValidation\`；尚未啟動 GUI，也未以實際圖片執行端到端檢測。先確認頻域對比勾選／取消後的預覽、參數保存與重載，再驗證 20 度線條、倍率 5、方向線框與熱圖是否避免滿版，以及分析耗時。之後再驗證影像載入與參數套用、物件搜尋、缺陷核心、尺寸條件及整合結果。另以代表性大圖驗證 `0.03X`、`0.04X`、`0.05X`、`0.06X`、`0.14X` 平移流暢度、清晰度及 ROI／MASK 對位。
