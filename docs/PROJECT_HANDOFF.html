TAKEOVER PLAYBOOK

接手與建置

先確認可還原的現場資料與依賴，再用固定影像／Recipe 建立接手基準。

  1. 保留現場基準記錄 commit、設定、Recipe、X/Y 精度與代表影像；備份執行目錄的重要資料。
  2. 補齊開發依賴Visual Studio / MSBuild、.NET Framework 4.7.2 Developer Pack、NuGet 套件與 SDK。
  3. 覆寫硬體 SDK 路徑指定 CameraSdkDirectory 與 LsiNativeDirectory，確認 managed / native DLL 都是相容版本。
  4. 以固定測例驗證結果先手動確認物件與 A/B/NG，再接相機與米輪；最後驗證總控、重連與連續運轉。

建置命令範例

msbuild .\MyApp4.sln /t:Build /p:Configuration=Debug /p:Platform="Any CPU" ^
  /p:CameraSdkDirectory="C:\SDK\Sapera" /p:LsiNativeDirectory="C:\SDK\LSI\x64"

上方換行使用 Windows cmd 的 ^；在 PowerShell 請合併成一行。SDK 路徑為範例，需改成實際目錄。兩專案皆指定 x64。

舊式 csproj 逐一列出 Compile；新增 C# 檔案時同步加入專案檔。Repository 目前沒有獨立自動化測試專案。本次僅製作與核對交接文件，未重新建置或執行設備驗收。

最少要帶走的驗收證據

程式 commit、影像 hash／尺寸、Recipe hash、ParameterId、X/Y 精度、預期與實際判定、耗時／RAM、硬體與站點組態，以及失敗時的紀錄。完整案例見 驗收與已知限制。

KNOWN LIMITS & VERIFICATION

接手優先確認的事項

以下是目前路徑與資料模型的風險摘要，尚無本次實機通過證據。接手時應重現、修正並保留驗證結果。

L01 · 優先切換頁面可能中斷本機連續檢測轉送

離開總覽會關閉 Overview 轉送，模式旗標可能保留且抑制自動檢測轉送。以影格序號驗證啟動、切頁、返回與停止。

來源：MainForm.InspectionOverview.cs · ExitInspectionOverviewMode
L02 · 優先同站快速重連的舊連線清理

舊 peer 的 finally 依 key 清理，可能移除同 key 新 peer。測試同 ID 重疊重連與多站操作。

來源：InspectionTcpTransport.cs · ReadLoopAsync / RemovePeer
L03歷史重跑未固定當時設備精度

歷史有參數快照，未包含當時全域 X/Y 精度；改標定後的 mm 量測與篩選結果可能改變。

來源：InspectionHistoryStore.cs、MainForm.InspectionHistory.cs
L05 / L10負載與保存完成狀態

巢狀平行、背景存圖及 DB 缺少一致的資源／排空策略。測磁碟滿、關閉程式及多小時運轉，確認圖片和紀錄一致。

來源：MainForm.CameraCapture.cs、MainForm.DetectionParameter.ResultReview.cs
L09TCP 最新狀態不保證逐筆結果送達

command-ack 是命令確認；目前沒有每筆檢測結果的可靠佇列與重送保證。以斷線／恢復案例確認現場需求。

來源：InspectionTcpTransport.cs、MainForm.ConnectionController.cs
